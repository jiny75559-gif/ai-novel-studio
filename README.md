# 叙事 · AI 小说工作台

面向 Windows 的本地小说创作软件，当前版本 v0.3.3。按桌面设计说明书 V2 开发，并参考已有小说工作流。项目正文和记忆保存在本机，支持自定义 Chat Completions 兼容 API。包含内置纳米老宋的双页阅读、离线文档导入，以及云端、ComfyUI、WebUI/Forge 插图接入。新版统一书架与写作台的界面，阅读设置收进面板，书本自动适配窗口。

作者拥有创作决定权。软件不内置题材白名单、内容过滤或审稿删改规则；题材、人物、大纲、正文和设定可自由编辑。副 AI 提供建议，作者可以采纳、忽略或标记为有意安排。所选 API 服务本身的输出能力和规则由服务商决定。


## v0.3.3 更新提示修复

更新失败后清除过期的“正在下载”或“正在安装”状态，保留明确错误并恢复重试及本地更新入口。慢网络下载分别设置连接、读取停滞和全程时限，减少传输未完成就触发旧180秒总时限的情况。包含 v0.3.2 的全部修复。

## v0.3.2 摘要与记忆修复

增加 DeepSeek 思考模式适配与手动开关，区分空正文、仅推理和长度截断；失败也保留输入/输出/推理用量。记忆输出按预算限制长度，半截 JSON 不提交，失败任务可手动重新提取。官方 DeepSeek 自动模式仅关闭结构化任务思考，正文与其他服务仍沿用服务默认；不自动改模型或提高付费输出预算。上下文配置上限提高至 200 万，50 万可正常保存；实际容量须以服务商为准。详见 [DeepSeek 记忆提取说明](docs/deepseek-memory.md)。

## 安装与开始写作

Windows 10/11 x64：运行发行目录中的 `AI-Novel-Studio-0.3.3-Setup.exe`。安装包内置 Microsoft Edge WebView2 离线安装组件，缺少时自动安装，无需联网或手动配置 Node.js、Rust、Python。升级继续读取本机既有作品。单独运行 `AI-Novel-Studio-0.3.3.exe` 的免安装方式需要电脑已有 WebView2；跨电脑分发建议使用安装包。

无需 AI 也可以从主页“导入书籍”，阅读 TXT、Markdown、DOCX、未加密 EPUB、PDF、HTML/HTM/XHTML、FB2（含 FB2.ZIP/FB2Z/FBZ）、RTF、ODT 和 CBZ。双页阅读支持翻页、书签、高亮、批注、全文搜索、图片放大、主题、字体、字号、行距、段距、页边距、进度拖动和专注模式，并可返回编辑本章。插图在“插图与形象”配置；人物定妆经作者确认后固定，后续图传入参考图片与有效的外貌变化。作品卡可选择“编辑作品”或“电子书阅读”。PDF 保留原页面和内嵌图片；EPUB 解析 nav/NCX 多级目录并保留插图与脚注；DOCX 正文插图、脚注与标题也会导入。阅读状态单独保存到 SQLite，长目录按可见行显示，并在章节末尾预排下一节。操作与接口细节见 [阅读与插图说明](docs/reading-and-images.md)。

人物外貌不必逐项手填：配置主 AI 后可“从正文读取形象”，核对原文引用并采用，补建文章里新出现的人物。已有角色首次生成定妆时，空形象卡会自动读取当前及之前章节。已确认的固定形象保留，正文明确写出的衣着、发型等变化可独立确认；提取后改稿会阻止过期结果写入。超长正文按模型上下文容量读取，面板会提示未完整读取的情况。

1. 打开软件，点击“新建作品”。可以先创建“雾港灯塔”示例，查看三章大纲、人物、关系和锁定设定。
2. 进入“模型与设置”，添加 API 的名称、完整 Base URL、准确模型 ID 和密钥。地址可填服务商的 `/v1` 基址，也可填完整 `/chat/completions` 地址。
3. 点击“测试连接”，再为当前作品选择主 AI 和副 AI，点击“保存项目设置”。同一个配置也可担任两个角色。
4. 在“故事大纲”填写总纲，并创建章节卡。每章至少填写目标或事件；结尾状态有助于章节衔接。
5. 在“人物关系”创建人物卡，填写状态和人物已知/未知信息。拖动人物安排位置，通过连线添加有向关系；关系可填写生效章节和可见范围。“树形视图”显示网络的投影。
6. 在“文风”选择默认预设或自行填写风格卡。参考小说支持 TXT 的 UTF-8/GB18030；导入后显示前中后三段样本，确认发送后分析，最后由作者保存风格卡。原小说不作为每章固定上下文。
7. 回到写作台，点击“生成本章”。确认目标字数、调用上限和上下文后开始；只生成当前章。
8. 直接在正文中改稿。工作副本约 1.5 秒自动保存；“保存版本”保留不可变历史。确认当前版本后，点击“下一章”。若在设置中开启“点击下一章时开始生成”，资料齐全且无关键警告时即可一次点击续写。

## 写作预设

“模型与设置 → 管理预设 / 导入酒馆”提供独立预设面板，支持常见 SillyTavern Chat Completion JSON、条目顺序/开关/角色/深度、常用宏与正文生成参数，预览真实请求后保存到库或绑定当前作品。作者大纲、禁止事项、确认设定与改稿融合到同一工作流；摘要和审稿保持自己的结构化协议。每个作品绑定独立副本。未支持宏会提示，默认暂停。兼容范围、变量生命周期与映射见 [预设说明](docs/writing-presets.md)。

API 配置可先保存再补模型 ID，支持读取模型列表和本地免密；错误在对话框内展示并保留 Key，主副 AI 选择即时保存。

## 改稿、审稿与记忆

正文始终是可编辑的纯文本。正常关闭窗口前也会保存未落盘的正文；保存失败时保留窗口。AI 修订生成待比较版本，不覆盖正在编辑的稿件。“版本”可以比较并采用历史稿；采用会形成新版本，不删除旧稿。

“开始审稿”调用副 AI，检查逻辑、人物知识、前后文、大纲和文字问题。每个问题含正文引文、来源和建议；宿主会核验引文。可把问题标为修订、忽略或有意安排，再执行所选修订。作者也可跳过审稿并直接确认正文。

**让改稿影响后续章节：修改 → 保存版本 → 确认本章。** 后续请求使用已确认正文的结尾，并携带作者相对 AI 稿的累积修改。修改更早章节也会进入后续上下文；被删掉的旧段落会明确标为失效文本。旧摘要、依赖旧正文的事实和后续章节会提示需要重新核实，避免继续沿用旧剧情。

确认章节后，可在右侧“记忆”点击“提取摘要与记忆”。AI 提取的事实先进入待审批列表，作者同意后才进入事实库；可以拒绝或手动调整。作者设定也可在“设定与记忆”中直接创建和修改。确认是指定供 AI 延续的版本，之后仍可重新编辑和确认新版。

## API 配置和恢复

- 输出参数可选 `max_tokens`、`max_completion_tokens` 或省略；温度可关闭，JSON object 模式可选。按服务商支持能力填写，错误不会自动反复重发。
- 远程接口使用 HTTPS。本地服务可在配置中允许 `http://127.0.0.1` / `localhost` 回环地址；需要提供兼容 Chat Completions 的服务。
- 超时或断线保留已完成场景。在任务记录中查看片段，修正配置后手动恢复；恢复会另开任务，只请求缺失场景。资料改变后会要求重新生成，以免拼接不同大纲。
- 被截断的输出不会当成成功章。请提高模型输出上限后恢复。取消会阻止迟到结果写入，服务商已经收到的请求可能已计费。
- 目标汉字数和上下文 token 数为估算，模型字数可能有偏差。单章调用上限是可调资源预算，审稿另有最多两次结构校验请求；风格分析一次请求。


## 字数、上下文与超时

“模型与设置”实时显示场景数、调用需求、预计输入加输出预算及超时风险。预算采用主 AI 的有效参数，包含酒馆预设覆盖，并检查后续场景随正文增长后的请求。资料或预计请求超出窗口时，在发送前提示修正；每次实际请求再次检查。单章调用上限不会延长单次请求的超时。

较长章节或慢模型可把请求超时设为 120～300 秒，并按实际速度调整；输出上限需能容纳每个场景。上下文只能填写模型真实支持的容量，不能通过提高设置让模型获得更大容量。估算不等于服务商精确 token 数，响应速度与实际字数仍由模型决定；失败保留已完成片段，不自动重复付费请求。

## 软件更新

侧栏 **软件更新 → 检查新版 → 下载并更新** 使用独立的 [GitHub Releases](https://github.com/jiny75559-gif/ai-novel-studio/releases)。未来更新下载约 39 MiB 的应用安装器，沿用已安装的 WebView2，无需反复下载约 246 MiB 的首次离线安装包。旧版 v0.3.0 需要先安装一次 v0.3.3，以后可在软件内更新。

无法访问 GitHub 时，可在此面板选择发行页的 `.nsupdate` 文件并一键安装。更新清单有发布者签名，安装程序核验 SHA-256；软件保存正文和阅读位置、备份数据库后再安装并重启。正在生成时需先完成或停止任务；本地同版本包可修复安装，更旧版本会被拒绝。更新不携带作品或 API 密钥，不向 GitHub 上传小说。详见 [格式与更新说明](docs/formats-and-updates.md)。

## 数据和备份

“模型与设置”显示实际数据目录。默认由 Tauri 的 Windows 应用数据目录解析，数据库名 `novel-studio.sqlite3`。不要在应用运行时单独复制数据库文件，SQLite 可能正在使用 WAL。

窗口右上角可导出正文 TXT 或完整项目 ZIP。项目包包含章节历史、大纲、人物关系、风格、摘要和记忆；不包含 API 密钥或本机数据路径。导入会创建新项目和新 ID。模型配置需要重新选择。主页提供作品回收站。

密钥保存到 Windows 凭据管理器，前端读取不到已保存的密钥。若系统凭据库不可用，则仅当前会话保存并显示提示，退出后重新填写。项目、任务快照和备份不存储密钥。

## 当前版本的边界

这是能够实际使用的第一版，尚未宣称设计说明书的全部正式验收项完成。已完成基本写作、人物网络、记忆审批、证据审稿、定点修订、版本历史和项目备份。当前尚未实现人物合并、长篇 FTS/向量检索、段落高亮 diff、精确成本报价、全文式章节覆盖报告、自动全书连写。在线更新与本地一键更新已实现。

初版上下文使用章节时间条件、已确认事实、最近三章有效摘要、前章结尾和作者改稿。超长作品需要维护摘要和人物卡；必要资料超过设置窗口时会提示调整，不静默丢掉作者改稿。正文以场景合成，暂未加入额外模型合章检查。主、副 AI 的实际质量取决于所选模型。

支持 Windows x64；未验证 macOS/Linux。已用本地模拟 HTTP 服务和真实桌面程序验证，没有调用用户付费 API。安装包尚未代码签名，首次运行可能出现 Windows 发布者提示。

## 开发

技术栈：Tauri 2、React、TypeScript、Vite、Rust、SQLite。模型请求、凭据、版本校验、任务调度和文件导入由 Rust 处理。普通网页只用于界面预览，实际保存和生成需要桌面宿主。

安装 Node.js 22+、Rust stable、Visual Studio C++ Build Tools 和 WebView2 后，在源码目录执行：

```powershell
npm ci
npm run desktop
```

检查和打包：

```powershell
npm run typecheck
npm run lint
npm test
npm run test:rust
cargo +stable clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
npm run package
```

本地测试 API：`npm run mock`，默认 `http://127.0.0.1:8787/v1`，测试模型 ID `mock-writer`，任意非空测试密钥。模拟服务仅用于测试，不随软件启动，不会伪造生产响应。桌面 CDP 测试在 `scripts/desktop-e2e.mjs` 与 `scripts/desktop-recovery.mjs`，需要独立 QA 数据目录和启用 WebView2 调试端口；见验证记录。

完整说明书见 `docs/spec-v2.md`；设计调整见 `docs/adr/001-local-first.md`；开源参考见 `docs/open-source-research.md`；实际测试记录见 `docs/validation.md`。
