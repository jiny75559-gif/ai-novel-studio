# DeepSeek 摘要与记忆排错 · v0.3.2

“上下文窗口”决定一次请求允许放多少输入和输出；“输出上限”是单独的生成预算。上下文设置成 50 万，并不会把输出上限从 4096 变成 50 万。思考模型可能先消耗推理预算，再返回最终 JSON；达到长度限制时，可能只有推理或半截 JSON。DeepSeek 官方也说明 JSON 模式偶尔会返回空正文。

## 新版操作

1. 在“模型与设置 → 编辑配置”确认准确模型 ID。输出上限与作品上下文分别设置；常规提取可先使用 8192 输出，再按模型能力和实际用量调整。
2. “思考模式”默认自动适配：官方 `api.deepseek.com` 的摘要、审稿、修订和文风/形象等结构化任务发送关闭思考；正文写作沿用服务默认，其他兼容接口自动模式不加此参数。开启/关闭思考可由作者手动选择，仅适用于支持 `thinking` 参数的服务；不改模型 ID。
3. 如果 JSON object 模式仍返回空正文，可关闭“接口支持 JSON object”后手动重试。软件仍检查 JSON 字段与原文证据。
4. 回写作台“任务”，在失败记录点“重新提取摘要与记忆”。失败不会自动重复请求；若是字段格式错误，既有流程最多额外修复一次格式。截断和空正文不会自动重发，不增加隐蔽付费请求。

本版按输出预算控制摘要、候选事实和引文长度，优先提取影响后续剧情的变化。非常小的输出预算仅生成简短摘要，可提高输出上限后重新提取候选。候选仍须作者审批，原始推理不会当成事实，不完整 JSON 不提交。已有正文与不可变历史保留。

任务记录显示输入、输出和服务商报告的推理 token。输出 token 通常已含推理，显示推理明细时不再重复加到总用量。服务商未提供统计时无法推算真实费用。

## 50 万上下文

v0.3.1 的前端和后端限制为 20 万，输入 50 万会保存失败；v0.3.2 已统一支持最大 200 万的配置范围，API 和预设输出配置也支持更大预算。**设置上限不代表模型真实容量**，仍须按准确模型的服务商说明填写；不要通过扩大设置绕过实际模型限制。请求仍保留保守估算和发送前检查。

## 验证范围

已用本地 HTTP 模拟响应复现空正文、仅推理、长度截断和读取响应超时，验证失败用量保留、半截 JSON 不入库、手动重试与审批。另外按最新截图补测事实列表优先、引文中途截断、1284汉字及9725总token的响应，确认原片段保留，重新提取成功后不带入半截事实。没有调用用户付费 API。本机没有截图对应的服务商原始响应，不能断言它们具体由哪一种服务端行为导致；上述修复分别覆盖这些返回路径。

依据：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/)、[Chat Completions 参数](https://api-docs.deepseek.com/api/create-chat-completion/)。响应速度、输出质量及服务端偶发错误仍取决于所选服务。
