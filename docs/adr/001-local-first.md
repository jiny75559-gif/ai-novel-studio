# 本地桌面与存储设计

保留设计说明书的 Windows、Tauri 2、React、TypeScript、Rust 和 SQLite 架构。所有业务写入、请求和任务状态由 Rust 统一校验，前端只负责编辑和显示。

首个可运行版本把人物、关系、事实、风格卡和审稿报告保存为带版本号的项目聚合 JSON。章节 ID、不可变正文版本、任务、片段、模型配置和事件记录使用独立 SQLite 表。这样降低初版维护的表数量，同时保持 SQLite 事务、项目乐观锁、不可变正文历史、唯一任务锁和可恢复片段。后续可通过迁移拆出聚合中的表。数据库唯一约束和内容不可变触发器由宿主执行。

API 参数由用户明确配置，支持 max_tokens、max_completion_tokens 或省略，temperature 可关闭，JSON object 可选。默认使用文本 JSON 校验，不假定兼容服务具有结构化输出能力。发生网络不确定性时不自动重发，用户手动恢复，防止静默重复计费。

把作者确认权集中于“确认章节”和“审批记忆”。修订先形成待比较版本，作者选择采用。下一章缺大纲会进入规划页。关系网络提供树形投影，树不作为底层存储。

参考小说只抽样分析抽象风格；保存风格卡而不保留原小说。前端展示实际将发送的样本并取得同意。低于 2000 字的目标供短章/测试使用，默认仍为 3000 汉字。

通过 [Tauri 单实例插件](https://v2.tauri.app/plugin/single-instance/) 保证同一应用只运行一个主进程；再次启动聚焦现有窗口，避免第二个进程把正在执行的任务误判为上次中断。项目与正文仍保留 expectedRevision 冲突校验。

作者已确认改稿的累积差异作为必要上下文加入之后的章节，不仅取前章结尾；多个手动版本向上追溯到原 AI 稿。更早章的作者修改也参与后续上下文。必要资料超预算时明确提示，未审批记忆仍不注入。
